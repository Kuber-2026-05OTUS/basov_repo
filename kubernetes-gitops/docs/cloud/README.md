# Инструкция для администратора Yandex Cloud

В данном документе описаны шаги по подготовке облачной инфраструктуры Yandex Cloud, применению студенческого промокода, запуску решения, его проверке и последующему отключению для экономии средств.

## 1. Оплата и применение ваучера студента на скидку

Для активации студенческого промокода (гранта) в Yandex Cloud:
1. Перейдите в консоль управления Yandex Cloud.
2. В правом верхнем углу нажмите на значок виджета баланса и выберите **Активировать промокод** (или перейдите в сервис **Yandex Cloud Billing**, выберите ваш платежный аккаунт и на панели слева нажмите **Активировать промокод**).
3. Введите полученный студенческий промокод и нажмите **Активировать**.
4. Убедитесь, что бонусные средства зачислены на баланс (в разделе "Гранты" или "Детализация"). Только после этого переходите к созданию платных ресурсов, чтобы списания шли с гранта, а не с привязанной банковской карты.

## ⚠️ ВАЖНО: Как не потратить купон (1000 ₽) за полчаса тестирования

Если при создании кластера вы выберете настройки для Production-среды (например, **Высокодоступный мастер на 3 хоста с 2 vCPU / 8 ГБ RAM**), базовая стоимость только одного мастера составит около **15 552,00 ₽ в месяц** (или ~21,6 ₽ в час). 
Хотя за полчаса самого тестирования вы потратите всего около 15-30 ₽ (включая узлы), **если вы забудете удалить кластер, ваш купон на 1000 ₽ полностью сгорит всего за 2 дня!**

Чтобы минимизировать расходы и гарантированно уложиться в лимит купона, используйте следующие настройки для учебного стенда:

1. **Тип мастера**: Выбирайте **Базовый (1 хост)** вместо *Высокодоступный (3 хоста)*. Это сразу снизит стоимость мастера в 3 раза.
2. **Вычислительные ресурсы мастера**: Для базового тестирования достаточно минимальных ресурсов (например, 2 vCPU, 4 ГБ RAM вместо 8 ГБ).
3. **Группы узлов (Node Groups)**:
   - **Тип ВМ**: Обязательно используйте **Прерываемые ВМ (Preemptible)**. Они стоят на 50-70% дешевле обычных.
   - **Ресурсы узлов**: Выбирайте минимально необходимые ресурсы (например, 2 vCPU, 4 ГБ RAM с гарантированной долей vCPU 20% или 50%, если доступно).
   - **Тип диска**: Выбирайте стандартный HDD (`network-hdd`) минимального объема (например, 30 ГБ), а не дорогие SSD.
4. **Удаление ресурсов**: Самое главное правило — **удаляйте кластер СРАЗУ после завершения проверки** (см. раздел 4).

## 2. Запуск решения

1. **Создание кластера Kubernetes:**
   - Перейдите в сервис **Managed Service for Kubernetes**.
   - Создайте новый кластер (выберите зональный или региональный кластер в зависимости от требований к отказоустойчивости).
   - Настройте сетевые правила и сервисные аккаунты согласно документации Yandex Cloud.

2. **Создание пулов узлов (Node Groups):**
   - Создайте пул узлов для рабочей нагрузки (`worker-pool`), достаточно 1 ноды.
   - Создайте пул узлов для инфраструктурных сервисов (`infra-pool`), достаточно 1 ноды.
   - При создании `infra-pool` в разделе "Теинты узлов" (Taints) добавьте правило:
     - Ключ: `node-role`
     - Значение: `infra`
     - Эффект: `NoSchedule`

3. **Установка ArgoCD и деплой приложений:**
   - Подключитесь к кластеру через `kubectl` (используя команду `yc managed-kubernetes cluster get-credentials ...`).
   - Установите ArgoCD с помощью Helm, применив конфигурацию `values.yaml` из директории `argocd` (она обеспечит установку ArgoCD только на `infra-pool`).
   - Примените манифесты GitOps:
     ```bash
     kubectl apply -f argocd/project-otus.yaml
     kubectl apply -f argocd/app-networks.yaml
     kubectl apply -f argocd/app-templating.yaml
     ```

## 3. Проверка решения

1. **Проверка узлов и подов:**
   - Убедитесь, что поды ArgoCD запущены исключительно на ноде из `infra-pool`:
     ```bash
     kubectl get pods -n argocd -o wide
     ```
2. **Проверка UI ArgoCD:**
   - Получите пароль администратора:
     ```bash
     kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d
     ```
   - Пробросьте порт: `kubectl port-forward svc/argocd-server -n argocd 8080:443`
   - Зайдите на `https://localhost:8080` и убедитесь, что приложения `kubernetes-networks` и `kubernetes-templating` имеют статус `Healthy` и `Synced`.
3. **Проверка рабочих нагрузок:**
   - Убедитесь, что поды приложений запущены на ноде из `worker-pool`:
     ```bash
     kubectl get pods -n homework -o wide
     kubectl get pods -n HomeworkHelm -o wide
     ```

## 4. Отключение облака

Чтобы избежать лишних списаний средств с гранта или банковской карты после завершения работы, необходимо удалить созданные ресурсы:

1. **Удаление кластера Kubernetes:**
   - В консоли управления перейдите в **Managed Service for Kubernetes**.
   - Выберите созданный кластер и нажмите **Удалить**.
   - Альтернативно через CLI:
     ```bash
     yc managed-kubernetes cluster delete <имя_или_id_кластера>
     ```
2. **Очистка сети (опционально):**
   - Если вы создавали отдельные VPC (сети) и подсети, статические публичные IP-адреса или балансировщики нагрузки (Network Load Balancer / Application Load Balancer), перейдите в соответствующие разделы (Virtual Private Cloud, Network Load Balancer) и удалите их.
3. **Проверка биллинга:**
   - Перейдите в **Yandex Cloud Billing** и убедитесь, что в разделе "Потребление" нет активных дорогостоящих ресурсов.
