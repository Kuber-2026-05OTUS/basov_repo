# Инструкция для администратора Yandex Cloud

Данная инструкция описывает шаги по работе с Yandex Cloud для развертывания решения kubernetes-vault.

## 1. Регистрация и оплата
1. Перейдите на сайт [Yandex Cloud](https://cloud.yandex.ru/) и авторизуйтесь с помощью Яндекс ID.
2. Перейдите в консоль управления (Консоль).
3. Создайте платежный аккаунт, если он еще не создан. Для этого перейдите в раздел "Биллинг" -> "Создать платежный аккаунт".
4. Привяжите банковскую карту для активации аккаунта (с карты спишется и вернется небольшая сумма для проверки).

## 2. Применение студенческого ваучера на скидку
1. В консоли управления перейдите в раздел "Биллинг".
2. Выберите ваш платежный аккаунт.
3. Перейдите на вкладку "Промокоды" (или "Гранты").
4. Нажмите "Активировать промокод" и введите код студенческого ваучера.
5. Убедитесь, что грант зачислен на ваш баланс. Средства гранта будут расходоваться в первую очередь.

## 3. Важно: Как не потратить грант (1000 ₽) впустую
Если при создании кластера выбрать тип мастера **Высокодоступный (3 хоста)** с ресурсами 2 vCPU и 8 ГБ RAM, стоимость только мастера составит более **15 500 ₽ в месяц** (около 21 ₽ в час на 30 июля 2026 года). Вместе с рабочими узлами баланс в 1000 ₽ может исчерпаться очень быстро, особенно если забыть удалить ресурсы.

Чтобы уложиться в лимит и максимально сэкономить:
1. **Тип мастера:** Обязательно выбирайте **Базовый (1 хост)** вместо Высокодоступного. Для выполнения домашнего задания отказоустойчивость мастера не требуется.
2. **Вычислительные ресурсы мастера:** Укажите минимально доступные для базового кластера.
3. **Рабочие узлы (Группа узлов):** 
   - В настройках узлов выбирайте **Прерываемые ВМ** (Preemptible) — они стоят на ~70% дешевле обычных.
   - Используйте небольшие диски (например, 30-50 ГБ `network-hdd`).
   - Доля vCPU: если доступно, выбирайте 20% или 50% для дополнительной экономии.
4. **Время жизни:** Главное правило — **сразу же удаляйте кластер и группу узлов** после того, как закончили проверку задания (см. пункт 6). За полчаса-час работы базового кластера с прерываемыми узлами спишется всего несколько рублей.

Подробнее о тарифах: [Цены на Managed Service for Kubernetes](https://yandex.cloud/ru/docs/managed-kubernetes/pricing)

## 4. Запуск решения (Managed Kubernetes)
1. В консоли Yandex Cloud перейдите в каталог (Folder), в котором будете работать.
2. В меню слева выберите "Managed Service for Kubernetes".
3. Нажмите "Создать кластер".
4. Укажите имя кластера, выберите сервисную учетную запись для ресурсов и для узлов (создайте новые, если их нет, с ролями `editor` и `container-registry.images.puller`).
5. Выберите сеть и подсети для кластера. В блоке "Конфигурация мастера" укажите тип **Базовый (1 хост)**.
6. Нажмите "Создать кластер" и дождитесь его перехода в статус `Running`.
7. Перейдите на вкладку "Группы узлов" и нажмите "Создать группу узлов".
8. Укажите имя группы, выберите 3 узла в блоке "Масштабирование" (фиксированный размер: 3).
9. Выберите конфигурацию вычислительных ресурсов (например, 2 vCPU, 4 ГБ RAM, **Прерываемые ВМ**).
10. Нажмите "Создать" и дождитесь готовности узлов.
11. Настройте `kubectl` для подключения к кластеру:
    ```bash
    yc managed-kubernetes cluster get-credentials <имя_кластера> --external
    ```

## 5. Проверка решения
1. Убедитесь, что узлы готовы:
    ```bash
    kubectl get nodes
    ```
    Статус всех 3 узлов должен быть `Ready`.
2. Выполните шаги по развертыванию Consul, Vault и External Secrets Operator согласно инструкциям в `kubernetes-vault/README.md`.
3. Проверьте, что секрет успешно синхронизировался из Vault в Kubernetes:
    ```bash
    kubectl get secret otus-cred -n vault
    ```

## 6. Отключение облака (Удаление ресурсов)
Чтобы избежать лишних списаний средств после завершения работы, необходимо удалить созданные ресурсы:
1. Удалите группу узлов Kubernetes:
   - В разделе "Managed Service for Kubernetes" выберите ваш кластер.
   - Перейдите на вкладку "Группы узлов", выберите группу и нажмите "Удалить".
2. Удалите сам кластер Kubernetes:
   - На странице списка кластеров нажмите на три точки напротив вашего кластера и выберите "Удалить".
3. Удалите созданные диски и балансировщики нагрузки (если они создавались автоматически сервисами Kubernetes, они должны удалиться вместе с кластером, но лучше проверить разделы "Compute Cloud" -> "Диски" и "Network Load Balancer").
4. При необходимости удалите каталог (Folder), если он использовался только для этого задания.
