# Инструкция для администратора Yandex Cloud

Данная инструкция описывает шаги по работе с Yandex Cloud для развертывания решения kubernetes-debug.

Задание прямо допускает выполнение как в minikube, так и в Managed Kubernetes
в Yandex Cloud — эта инструкция нужна только для второго варианта.

## 1. Регистрация и оплата
1. Перейдите на сайт [Yandex Cloud](https://cloud.yandex.ru/) и авторизуйтесь с помощью Яндекс ID.
2. Перейдите в консоль управления (Консоль).
3. Создайте платежный аккаунт, если он еще не создан. Для этого перейдите в раздел "Биллинг" -> "Создать платежный аккаунт".
4. Привяжите банковскую карту для активации аккаунта (с карты спишется и вернется небольшая сумма для проверки).

## 2. Применение студенческого ваучера на скидку
1. В консоли управления перейдите в раздел "Биллинг".
2. Выберите ваш платежный аккаунт.
3. Перейдите на вкладку "Промокоды" (или "Гранты").
4. Нажмите "Активировать промокод" и введите код студенческого ваучера.
5. Убедитесь, что грант зачислен на ваш баланс. Средства гранта будут расходоваться в первую очередь.

## 3. Как не потратить грант впустую
Это одно из самых дешевых заданий серии: нагрузка — один под с nginx и
кратковременные отладочные поды/контейнеры, которые удаляются сразу после
использования. Тем не менее правила экономии те же, что и в остальных
заданиях:

1. **Тип мастера:** **Базовый (1 хост)**, не Высокодоступный.
2. **Рабочие узлы:** 1 узел достаточно (отладка ноды в задании выполняется
   на той же ноде, где работает под с nginx) — **Прерываемая ВМ**
   (Preemptible), минимальная конфигурация (2 vCPU / 4 ГБ RAM).
3. **Отладочные поды и эфемерные контейнеры** (`kubectl debug ...`) не
   тарифицируются отдельно — это часть той же ноды/пода, но их стоит
   удалять сразу после того, как вывод команд получен и сохранен
   (`kubectl debug` не удаляет эфемерные контейнеры автоматически до
   завершения пода; отладочные поды ноды — обычные поды, их нужно удалить
   вручную: `kubectl delete pod <node-debug-pod-name>`).
4. **Время жизни:** удаляйте кластер сразу после того, как собрали все
   требуемые в задании артефакты (манифест, вывод `ls -la`, `tcpdump`,
   логи, вывод `strace`).

Подробнее о тарифах: [Цены на Managed Service for Kubernetes](https://yandex.cloud/ru/docs/managed-kubernetes/pricing)

## 4. Запуск решения (Managed Kubernetes)
1. В консоли Yandex Cloud перейдите в каталог (Folder), в котором будете работать.
2. В меню слева выберите "Managed Service for Kubernetes".
3. Нажмите "Создать кластер".
4. Укажите имя кластера, выберите сервисную учетную запись для ресурсов и для узлов (создайте новые, если их нет, с ролями `editor` и `container-registry.images.puller`).
5. Выберите сеть и подсети для кластера. В блоке "Конфигурация мастера" укажите тип **Базовый (1 хост)**.
6. Нажмите "Создать кластер" и дождитесь его перехода в статус `Running`.
7. Перейдите на вкладку "Группы узлов" и нажмите "Создать группу узлов".
8. Укажите имя группы, выберите 1 узел в блоке "Масштабирование" (фиксированный размер: 1 — этого достаточно, отладка ноды выполняется на этой же ноде).
9. Выберите конфигурацию вычислительных ресурсов (например, 2 vCPU, 4 ГБ RAM, **Прерываемые ВМ**).
10. Нажмите "Создать" и дождитесь готовности узла.
11. Настройте `kubectl` для подключения к кластеру:
    ```bash
    yc managed-kubernetes cluster get-credentials <имя_кластера> --external
    ```

## 5. Выполнение задания и проверка решения
1. Убедитесь, что узел готов:
    ```bash
    kubectl get nodes
    ```
2. Выполните шаги из `kubernetes-debug/scripts/debug_session.sh` по порядку:
   применение манифеста пода, создание эфемерного контейнера с `--target=nginx`,
   получение `ls -la /proc/1/root/etc/nginx`, запуск `tcpdump`, генерация
   трафика, бонусный `strace -p 1` с профилем `--profile=sysadmin`, и
   отладка ноды через `kubectl debug node/<node>`.
3. На каждом шаге сохраняйте вывод команд — это и есть результат ДЗ,
   который нужно приложить (манифест, `ls -la`, вывод `tcpdump`, логи пода,
   вывод `strace`).
4. Проверьте, что под с nginx в статусе `Running`:
   ```bash
   kubectl get pod -n debug-demo distroless-nginx
   ```

## 6. Отключение облака (Удаление ресурсов)
Чтобы избежать лишних списаний средств после завершения работы, необходимо удалить созданные ресурсы:
1. Удалите отладочные поды, если они еще существуют:
   ```bash
   kubectl get pods -n debug-demo
   kubectl get pods --field-selector=status.phase=Running -A | grep node-debugger
   kubectl delete pod <node-debug-pod-name>
   ```
2. Удалите демо-нагрузку:
   ```bash
   kubectl delete -f kubernetes-debug/k8s/pod-distroless-nginx.yaml -f kubernetes-debug/k8s/namespace.yaml
   ```
3. Удалите группу узлов Kubernetes:
   - В разделе "Managed Service for Kubernetes" выберите ваш кластер.
   - Перейдите на вкладку "Группы узлов", выберите группу и нажмите "Удалить".
4. Удалите сам кластер Kubernetes:
   - На странице списка кластеров нажмите на три точки напротив вашего кластера и выберите "Удалить".
5. Удалите созданные диски и балансировщики нагрузки, если они создавались (проверьте разделы "Compute Cloud" -> "Диски" и "Network Load Balancer").
6. При необходимости удалите каталог (Folder), если он использовался только для этого задания.
