# Инструкция для администратора Yandex Cloud

Данная инструкция описывает шаги по работе с Yandex Cloud для развертывания
решения kubernetes-prod. В отличие от других домашних заданий этого курса,
здесь не используется Managed Service for Kubernetes — кластер собирается
вручную с помощью kubeadm на обычных виртуальных машинах (Compute Cloud),
поэтому раздел 4 ниже про создание ВМ, а не про Managed Kubernetes.

## 1. Регистрация и оплата
1. Перейдите на сайт [Yandex Cloud](https://cloud.yandex.ru/) и авторизуйтесь с помощью Яндекс ID.
2. Перейдите в консоль управления (Консоль).
3. Создайте платежный аккаунт, если он еще не создан: "Биллинг" -> "Создать платежный аккаунт".
4. Привяжите банковскую карту для активации аккаунта (спишется и вернется небольшая сумма для проверки).

## 2. Применение студенческого ваучера на скидку
1. В консоли управления перейдите в раздел "Биллинг".
2. Выберите ваш платежный аккаунт.
3. Перейдите на вкладку "Промокоды" (или "Гранты").
4. Нажмите "Активировать промокод" и введите код студенческого ваучера.
5. Убедитесь, что грант зачислен на баланс. Средства гранта расходуются в первую очередь.

## 3. Как не потратить грант впустую

Это одно из самых дорогих заданий серии: основное задание требует **4 ВМ**
(1 master + 3 worker, каждая 2 vCPU / 8 ГБ RAM), а бонусное задание с * —
еще **5 отдельных ВМ** (3 master + 2 worker той же конфигурации) для
отказоустойчивого кластера через kubespray. Работающие одновременно 4-9
ВМ по 2 vCPU/8 ГБ RAM способны быстро исчерпать грант.

Чтобы уложиться в лимит:
1. **Прерываемые ВМ (Preemptible):** используйте их для всех узлов — они
   стоят на ~70% дешевле обычных и для домашнего задания подходят
   полностью.
2. **Диски:** используйте `network-hdd` минимального достаточного
   размера (кластеру kubeadm/containerd достаточно 20-30 ГБ на узел).
3. **Не держите оба кластера одновременно:** сначала выполните основное
   задание (4 ВМ) и удалите эти ВМ, затем при необходимости бонусного
   задания поднимите отдельные 5 ВМ для kubespray. Не создавайте 9 ВМ
   параллельно, если не нужно сравнивать оба кластера бок о бок.
4. **Время жизни:** удаляйте ВМ сразу после того, как собрали все
   требуемые в задании артефакты (`kubectl get nodes -o wide` до и после
   обновления, все выполненные команды).

Подробнее о тарифах: [Цены на Compute Cloud](https://yandex.cloud/ru/docs/compute/pricing).

## 4. Создание виртуальных машин (Compute Cloud)

Повторите для каждой из 4 ВМ основного задания (`master`, `worker-1`,
`worker-2`, `worker-3`); для бонусного задания — аналогично для 5 ВМ
(`master-1..3`, `worker-1..2`).

1. В консоли Yandex Cloud перейдите в каталог (Folder), в котором будете работать.
2. В меню слева выберите "Compute Cloud" -> "Создать ВМ".
3. Образ: Ubuntu 22.04 LTS.
4. Вычислительные ресурсы: 2 vCPU, 8 ГБ RAM (по условию задания), диск
   `network-hdd` 20-30 ГБ.
5. Прерываемость: включите "Прерываемая ВМ" для экономии.
6. Сеть: поместите все узлы будущего кластера в одну подсеть, чтобы они
   видели друг друга по внутренним IP.
7. Добавьте свой SSH-публичный ключ в разделе "Доступ".
8. Настройте группы безопасности (security groups) так, чтобы между
   узлами кластера были открыты порты, необходимые kubeadm/Flannel/etcd
   (6443, 2379-2380, 10250-10259, 8472/UDP для VXLAN Flannel), см.
   [официальный список портов kubeadm](https://kubernetes.io/docs/reference/networking/ports-and-protocols/).
9. Создайте ВМ и дождитесь готовности, запишите её внутренний IP.

## 5. Развертывание и обновление кластера

1. Скопируйте `kubernetes-prod/scripts/00-common-prep.sh` на каждую ВМ и
   выполните его (master и все worker).
2. На master выполните `01-master-init.sh` (укажите внутренний IP master
   в `MASTER_ADVERTISE_IP`). Сохраните команду `kubeadm join ...` из
   вывода.
3. На каждом worker выполните `02-worker-join.sh`, подставив в
   `JOIN_COMMAND` команду, полученную на шаге 2.
4. С master выполните `kubectl get nodes -o wide` — сохраните вывод, это
   один из результатов ДЗ.
5. Обновление: выполните `03-upgrade-master.sh` на master, затем
   `04-upgrade-worker.sh` поочередно (не параллельно!) для каждого
   worker.
6. Снова выполните `kubectl get nodes -o wide` — сохраните вывод после
   обновления, это второй обязательный результат ДЗ.
7. (Бонус) для kubespray-кластера следуйте `kubernetes-prod/kubespray/README.md`.

## 6. Отключение облака (удаление ресурсов)

Чтобы избежать лишних списаний после завершения работы:

1. Удалите все ВМ основного задания:
   - "Compute Cloud" -> выберите ВМ -> "Удалить" (повторите для всех 4).
2. Если поднимали бонусный кластер через kubespray, удалите все 5 его ВМ аналогично.
3. Проверьте и удалите оставшиеся диски: "Compute Cloud" -> "Диски".
4. Проверьте и удалите статические внешние IP-адреса, если резервировали
   отдельно: "VPC" -> "Публичные IP-адреса".
5. При необходимости удалите каталог (Folder), если он использовался
   только для этого задания.
