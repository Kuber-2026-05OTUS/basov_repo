# Руководство администратора Yandex Cloud

Данный документ описывает жизненный цикл управления облачной инфраструктурой в Yandex Cloud для работы с решением Kubernetes Logging (Loki, Promtail, Grafana), от оплаты и применения гранта (ваучера) до остановки потребления ресурсов.

## 1. Оплата и создание платежного аккаунта

Для создания ресурсов в Yandex Cloud необходимо иметь активный платежный аккаунт:
1. Авторизуйтесь в консоли управления [Yandex Cloud](https://console.cloud.yandex.ru/).
2. Перейдите в раздел **Биллинг** (Billing).
3. Нажмите кнопку **Создать платежный аккаунт**.
4. Укажите название аккаунта, страну и выберите тип лица (физическое лицо или юридическое лицо).
5. Привяжите банковскую карту. В процессе привязки будет списана и сразу возвращена небольшая сумма для проверки карты.
6. Выберите созданный платежный аккаунт в качестве основного для вашего облака.

## 2. Применение ваучера (гранта) студента

Студентам образовательных платформ (например, Otus) обычно предоставляется грант на использование Yandex Cloud:
1. В левом меню консоли управления Yandex Cloud выберите **Биллинг**.
2. Выберите ваш активный платежный аккаунт.
3. Перейдите на вкладку **Гранты** (или "Промокоды").
4. Нажмите кнопку **Активировать промокод** (или "Активировать грант").
5. Введите полученный от образовательной платформы код ваучера и нажмите **Активировать**.
6. Убедитесь, что баланс гранта пополнился. Средства за использование ресурсов будут в первую очередь списываться с этого гранта.

## 3. Оптимизация расходов (Как не потратить купон на 1000 рублей)

Если при создании кластера выбрать ресурсоемкие конфигурации (например, Высокодоступный мастер, 3 хоста по 2 vCPU / 8 ГБ RAM и включенное логирование), стоимость только управляющих узлов может составить **15 552,00 ₽ в месяц** (по тарифам Yandex Cloud). Ваш купон сгорит очень быстро даже при кратковременном тестировании (с учетом дополнительных затрат на worker-узлы).

Чтобы успешно выполнить ДЗ и сэкономить средства (потратив самый минимум за полчаса тестирования), **обязательно** примените следующие настройки при создании кластера:

1. **Тип мастера (Control Plane):** 
   - ❌ **НЕ выбирайте** `Высокодоступный` (3 хоста).
   - ✅ **Выберите** `Базовый` (1 хост). Для тестирования и выполнения ДЗ отказоустойчивость панели управления не требуется, а стоимость зонального (базового) мастера существенно ниже (а в некоторых случаях первый зональный мастер предоставляется бесплатно).
2. **Логирование в Yandex Cloud:**
   - ❌ **ОТКЛЮЧИТЕ** опцию `Запись логов` в настройках кластера. Поскольку в рамках задания вы самостоятельно разворачиваете Loki и Promtail для сбора логов, встроенное платное логирование Managed Kubernetes вам не нужно, оно будет вхолостую списывать деньги с баланса.
3. **Пулы узлов (Node Groups):**
   - ✅ В настройках вычислительных ресурсов воркеров выбирайте минимально необходимые значения: например, `2 vCPU` и `4-8 ГБ RAM`.
   - ✅ Используйте **Прерываемые виртуальные машины** (Preemptible VMs). Они стоят значительно дешевле обычных и идеально подходят для кратковременных тестов.
   - ✅ Снизьте гарантированную долю vCPU (например, до `20%` или `50%`), если позволяет конфигурация, — это дополнительно сократит расходы.
4. **Удаление кластера:**
   - ✅ Обязательно удалите кластер и пулы узлов **сразу же** после проверки ДЗ. Оставленные "на ночь" узлы быстро израсходуют весь ваш грант, так как тарификация идет даже за выключенные ВМ (за диски и IP-адреса).

## 4. Запуск решения

Развертывание инфраструктуры для централизованного логирования в Kubernetes:
1. **Создание кластера Managed Kubernetes:**
   - Перейдите в раздел **Managed Service for Kubernetes**.
   - Создайте кластер, выбрав нужную сеть, подсеть и сервисные аккаунты для управления. **Обязательно учитывайте рекомендации по экономии из пункта 3.**
2. **Настройка пулов узлов (Node Groups):**
   - Создайте пул для рабочей нагрузки (`workload-pool`).
   - Создайте пул для инфраструктуры (`infra-pool`). Установите в настройках узлов Taints: ключ `node-role`, значение `infra`, эффект `NoSchedule`.
3. **Настройка Object Storage (S3):**
   - Перейдите в раздел **Object Storage**.
   - Создайте бакет (например, `loki-logs-bucket`).
   - В разделе **Сервисные аккаунты** (Service Accounts) создайте аккаунт с ролями для доступа к бакету (например, `storage.editor`).
   - Сгенерируйте **статические ключи доступа** (Access Key ID и Secret Access Key).
4. **Установка компонентов логирования:**
   - Подключитесь к кластеру локально через `kubectl` и `yc managed-kubernetes cluster get-credentials ...`.
   - Внесите ключи доступа S3 в файл `loki-values.yaml`.
   - Разверните Loki, Promtail и Grafana с помощью Helm чартов (подробные команды описаны в основном `README.md` директории).

## 5. Проверка решения

1. Проверьте статус всех подов в кластере:
   ```bash
   kubectl get pods -n logging -o wide
   ```
   Поды Loki и Grafana должны располагаться на инфраструктурных нодах, поды Promtail — на всех.
2. Пробросьте порт к Grafana:
   ```bash
   kubectl port-forward svc/grafana 8080:80 -n logging
   ```
3. Откройте интерфейс Grafana (localhost:8080).
4. В разделе **Explore** выберите источник `Loki` и выполните тестовый запрос (например, `{app="promtail"}`).
5. Убедитесь, что логи корректно собираются, а метрики отображаются на графиках. Зайдите в интерфейс Yandex Object Storage и убедитесь, что в бакете начали появляться файлы чанков Loki.

## 6. Отключение облака и освобождение ресурсов

Чтобы избежать списания средств после окончания работы или исчерпания гранта, ресурсы необходимо удалить:
1. **Удаление Helm релизов (Опционально):**
   ```bash
   helm uninstall grafana promtail loki -n logging
   ```
2. **Удаление кластера Kubernetes:**
   - В консоли Yandex Cloud перейдите в **Managed Service for Kubernetes**.
   - Выберите ваш кластер и нажмите **Удалить**. Это автоматически удалит все пулы узлов (Node Groups) и связанные с ними вычислительные ресурсы.
3. **Очистка S3 бакета:**
   - Перейдите в **Object Storage**.
   - Выберите бакет с логами. Вам потребуется удалить все файлы внутри бакета (или настроить правило Lifecycle на удаление), после чего вы сможете удалить сам бакет.
4. **Удаление дисков и IP-адресов:**
   - Зайдите в **Compute Cloud** -> **Диски** и убедитесь, что не осталось "осиротевших" дисков.
   - Перейдите в **Virtual Private Cloud (VPC)** -> **IP-адреса** и освободите все статические публичные IP-адреса, если вы их резервировали.
5. Зайдите в **Биллинг**, чтобы убедиться, что тарифицируемых ресурсов больше нет и текущее потребление средств остановилось.
